## Findings considered and rejected

- **Keep GitHub Pages as the Cloudflare Worker's publishing target**: rejected
  because it adds GitHub credentials and Git commit/API orchestration to the
  Worker. The existing Worker already has RSS routes and can serve feeds directly.
- **Rely on a long-lived Browser Run session as the authenticated profile**:
  rejected because Browser Run sessions are operationally ephemeral and billed
  while open. Explicit encrypted Playwright storage-state persistence is easier
  to rotate, audit, and recover.
- **Store X storage state in Secrets Store**: rejected because the documented
  1,024-byte per-secret beta limit is too small/fragile for evolving browser
  state, and a Worker cannot use it as mutable per-run state. Store an AES key as
  a Worker secret and the encrypted state envelope in KV instead.
